## 1. 目标

这份方案的目标不是“删除结果”，而是：

- **保留所有源结果**
- **保留所有 PNG 图**
- **保留所有相关数据（CSV / tables / stats / report）**
- **减少重复复制出来的镜像层**
- **让 main 分支的 batch 输出更清楚、更不容易混版本**

一句话：

> 去重是为了减少重复副本，不是为了减少科研内容。

---

## 2. 不可触碰原则

以下内容在去重过程中**不能删**：

### 2.1 task 原始结果
- `batch/analysis/` 下各 task 的 `tables/`
- `batch/analysis/` 下各 task 的 `figures/`
- `batch/analysis/` 下各 task 的 `reports/`

### 2.2 batch 主结果
- `batch/merged/`
- `batch/qc/`
- `batch/paper/`
- `batch/audit/`
- `batch/reports/` 中真正承担主报告功能的文件

### 2.3 单被试结果
- `subjects/<subject_id>/tables/`
- `subjects/<subject_id>/figures/`
- `subjects/<subject_id>/qc/`
- `subjects/<subject_id>/report/`

### 2.4 你特别强调的内容
- **所有有分析意义的 PNG 图不能丢**
- **所有与这些图对应的统计数据和表格不能丢**

## 3. 当前输出层怎么分

当前 main 的 `batch/` 实际上是多层并存：

```text
batch/
├─ merged/        # 源表层
├─ qc/            # QC 源结果层
├─ reports/       # 报告/导航层
├─ audit/         # 审计层
├─ analysis/      # task 原始结果层
├─ paper/         # 论文/展示源图层
├─ descriptive/   # 描述性摘要层
├─ inferential/   # 推断性摘要层
├─ tables/        # 统一入口镜像层
└─ figures/       # 统一入口镜像层
```

问题不在于层数多，而在于：

- 源结果层已经有一套
- 摘要层又做了一套
- 镜像层又再拷一套

于是同一批内容可能在多个地方出现。

---

## 4. 哪些必须保留

## 4.1 源结果层（必须保留）
这些目录是“真正产出结果”的地方：

- `batch/merged/`
- `batch/qc/`
- `batch/analysis/`
- `batch/paper/`
- `batch/audit/`
- `subjects/<subject_id>/...`

这些目录里的内容具有：
- 原始性
- 可追溯性
- 科研解释价值
- 与图表一一对应的数据关系

所以这些不能因为“去重”被清掉。

---

## 4.2 摘要层（可以保留）
这些目录可以继续保留，但应该是“摘要层”，不是第二套完整结果层：

- `batch/descriptive/`
- `batch/inferential/`

这里适合放：
- 汇总后的关键表
- 汇总后的关键图
- 面向阅读的 README / report

但不适合无节制复制 task 原始结果。

---

## 5. 哪些属于重复副本

当前最值得去重的是：

### 5.1 统一镜像层
- `batch/tables/`
- `batch/figures/`

如果这些目录只是把别处已有的 PNG / CSV 再复制一遍，
那它们就是最典型的重复副本层。

### 5.2 重复导航文件
如果多个 README / report 只是重复描述相同内容，
而没有新增解释，也属于可收缩对象。

### 5.3 curated 层中的整份复制
如果 `descriptive/` 或 `inferential/` 中某些文件只是把 task 层结果整份搬过去，
而不是做摘要表达，那也应该被视为重复副本。

---

## 6. 去重不是删内容

这个项目的去重应该遵守下面这条规则：

> **保留源文件，减少重复拷贝。**

具体做法不是删除 PNG 和 CSV，
而是把“统一入口层”改成“索引层”。

例如以后更合理的做法是：

- 原图仍然留在原目录
- 原表仍然留在原目录
- `batch/figures/` 不再复制整份图，而是提供 `figures_index.csv`
- `batch/tables/` 不再复制整份表，而是提供 `tables_index.csv`
- `batch/reports/` 提供统一导航说明

这样：
- 内容不丢
- 图不丢
- 数据不丢
- 但目录不会继续膨胀

## 7. 安全推进步骤

### 第 0 步：先不删任何文件
先做盘点，不做删除。

### 第 1 步：做 inventory
把当前输出中的文件和目录分类成：
- `source`（源结果）
- `curated-summary`（摘要结果）
- `mirror-copy`（重复副本）
- `navigation-only`（纯导航）

### 第 2 步：明确主入口
告诉使用者：
- 原始结果看哪里
- 摘要结果看哪里
- 哪些只是方便导航，不是主版本

### 第 3 步：停掉未来的重复复制
修改代码，让未来运行时：
- 继续生成源结果
- 继续保留摘要层
- 不再额外复制整份 PNG / CSV 到镜像层

### 第 4 步：评审后再清理旧镜像
只有在 inventory 审核通过后，才考虑清理那些已经确认完全冗余的副本。
